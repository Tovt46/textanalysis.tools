# TextContract Agent — Nebius x NVIDIA Hackathon

## Problem and audience

Content and SEO teams often ask a model to make copy shorter, clearer, or more
natural while preserving prices, links, CTA behavior, structured data, legal
caveats, and the strength of factual claims. A fluent rewrite can silently
break those constraints. TextContract turns the brief into a reviewable rule
set before it permits generation.

The user supplies exactly one source document or HTML fragment and one rewrite
brief. Draft 1 and Repair 1 are generated by the agent and recorded as an audit
trail; they are not extra user inputs.

## Agent architecture

```text
source + brief
  -> deterministic rule extraction
  -> Nemotron contract compilation
  -> human contract approval
  -> Nemotron Draft 1
  -> deterministic + semantic + allowed Tavily checks
  -> optional Nemotron Repair 1
  -> final recheck
  -> READY | NEEDS REVIEW | BLOCKED
  -> human acceptance
```

The browser calls three short, stateless Next.js route handlers:

- `POST /api/text-contract/compile`
- `POST /api/text-contract/generate`
- `POST /api/text-contract/evaluate`

There is one compilation, one initial draft, one semantic evaluation, at most
one repair, and at most one re-evaluation. The application has no unbounded
autonomous loop and no CMS publishing step.

## NVIDIA Nemotron through Nebius Token Factory

`NEBIUS_MODEL_REASONING` is used for contract compilation and adversarial
semantic evaluation. `NEBIUS_MODEL_FAST` is used for Draft 1 and Repair 1. The
exact Nemotron model IDs are deployment configuration copied from Token
Factory, not hard-coded into the repository. Both configured choices must
support structured JSON responses.

The integration uses the OpenAI-compatible Token Factory endpoint at
`https://api.tokenfactory.nebius.com/v1/`. API credentials remain server-side.
Invalid JSON receives one bounded structured-output retry; authorization,
rate-limit, timeout, empty-output, and schema failures never become `READY`.

## Tavily flow

Nemotron can mark a contract rule `requiresLiveEvidence` only when the claim is
genuinely time-sensitive. Evaluation then sends that focused rule query to
Tavily with these bounds:

- maximum three live rules per run;
- `basic` search;
- maximum three returned sources per rule;
- supplied official domains used as a filter;
- missing or unusable sources become `uncertain`.

The evidence title, URL, and excerpt are displayed beside the rule. Tavily is a
functional runtime dependency for current claims, not a decorative lookup and
not a general-purpose fact checker.

## Privacy and security boundary

- The UI discloses that source and brief are sent to Nemotron before the first
  model request.
- The application does not persist a server-side workspace. The current tab
  uses versioned `sessionStorage`.
- Structured API logs contain operation, status, timing, size, request ID, and
  coarse error class—not source, brief, candidate, query, URL, or snippets.
- TextContract model routes are same-origin and rate-limited. They are not part
  of the public cross-origin analysis API.
- Source and model content are wrapped as untrusted data in model prompts.
- Results render as escaped textarea/code content; no submitted HTML executes.
- Source and candidate are capped at 30,000 characters, brief at 2,000, the
  contract at 20 rules, and live evidence at three rules.
- Nebius and Tavily remain independent processors governed by their policies.

## Demo

Open `/tools/text-contract`, choose **Load demo**, then **Build contract**. The
fixture contains `$5.99`, a `30-day` refund, five destinations, a CTA label and
attributes, cautious `may help` language, and FAQPage JSON-LD. Review the
contract, approve it, and run the guarded rewrite.

The runtime—not a hard-coded broken draft—creates Draft 1. If any rule fails,
the UI shows the finding and creates one Repair 1. The final screen provides the
candidate, source-to-draft and draft-to-repair previews, every rule evaluation,
Tavily evidence links, provider/model usage, human acceptance, and Markdown or
JSON export.

Intercepted responses are only for automated tests and must be labelled mocked
in any recording. A submission demo must run its draft, checks and repair through
real Nebius calls, plus at least one real Tavily-backed live rule. No seeded
failure is presented as a model-generated mistake.

## Evaluation

The repository contains deterministic mutation coverage and a labeled semantic
fixture corpus. Run:

```bash
npm test
npm run test:browser
npm run lint
```

Provider-free tests mock structured model calls and Tavily search so CI spends
no credits. Before submission, record separately:

- critical semantic recall target: at least 90%;
- harmless-paraphrase false-positive target: at most 10%;
- one-attempt repair success target: at least 80%;
- three consecutive real end-to-end runs;
- one real Token Factory smoke and one real Tavily smoke.

The opt-in provider smoke is:

```bash
RUN_LIVE_TEXT_CONTRACT_SMOKE=1 npm run smoke:text-contract-providers
```

These targets are not reported as achieved until the live evaluation has run.

## Known limitations

### September 4 hardening

Contract v2 includes its immutable original source and an approved revision.
Requests with changed source/brief/language, stale approval or missing source
guards are rejected. The client freezes edits during active steps, supports
cancellation, ignores stale responses and only enables Accept for a current,
fully checked READY result.

Deterministic rules group complete inventories instead of taking the first 14
matches. DOM parsing covers visible numeric values, repeated/fragment links,
CTA and accessibility attributes, closing headings, JSON-LD and microdata.
Invalid or duplicate model judgments and unverifiable supporting excerpts become
uncertain. Every attempt retains evaluations/evidence/errors. Manual edits are
persisted and failed rechecks can be retried. Diffs keep the complete texts.

Provider-free regression on three existing local HTML documents now detects
46/46 targeted mutations (previously 27/46); all three unchanged controls pass.
This is not Nemotron recall or repair-success measurement. Real provider tests
and the semantic targets above remain unverified until keys are configured.

### Remaining boundaries

- Semantic checks remain model judgments and can be uncertain.
- A search excerpt is not equivalent to a complete authoritative document.
- Structural guards are deliberately conservative: HTML attribute sets and
  JSON-LD contents are preserved, so changing those requires rebuilding the
  source contract. They do not validate computed CSS, external resources,
  factual accuracy, or the entire Schema.org specification.
- Session storage is tab-local and not collaboration or durable project
  storage.
- There is no account, database, CLI, MCP wrapper, CMS integration, or automatic
  publishing in the hackathon MVP.
- The output always requires a human acceptance decision.
